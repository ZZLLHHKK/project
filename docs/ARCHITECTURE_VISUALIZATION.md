## 2. 資料流向圖（適合詳細講解）

### 場景：用戶說「打開廚房燈」

```
用戶 ──(語音波形)──→ ┌─────────────┐
                    │ 麥克風輸入   │
                    │ (ALSA)      │
                    └──────┬──────┘
                           │ PCM buffer
                    ┌──────▼──────────┐
                    │ STT (Faster-    │
                    │ Whisper)        │
                    │ 語音→文字轉換   │
                    └──────┬──────────┘
                           │ 「打開廚房燈」
                    ┌──────▼──────────────┐
                    │ 語言偵測            │
                    │ (lang_detect)       │
                    │ Result: 中文        │
                    └──────┬──────────────┘
                           │ lang=zh
        ┌──────────────────▼──────────────────┐
        │    Agent 編排 (SmartHomeAgent)      │
        │                                     │
        │ Step 1: FastPath 查詢               │
        │ ├─ 規則 key: "打開*燈"              │
        │ └─ 匹配! → 抽取 location=廚房        │
        │                                     │
        │ Step 2: 執行 Action                 │
        │ ├─ device_type: light               │
        │ ├─ location: kitchen                │
        │ ├─ state: on                        │
        │ └─ 呼叫 device_controller.turn_on()│
        │                                     │
        │ Step 3: 更新狀態                    │
        │ └─ state_manager.set_state(...)    │
        │                                     │
        │ Step 4: 生成回覆文本                │
        │ └─ "已打開廚房燈"                   │
        └──────────────────┬──────────────────┘
                           │ 回覆文本 + lang=zh
                    ┌──────▼──────────┐
                    │ TTS (Piper)     │
                    │ 文字→語音       │
                    │ (中文語音模型)  │
                    └──────┬──────────┘
                           │ PCM audio
                    ┌──────▼──────────┐
                    │ 喇叭輸出        │
                    │ (ALSA)          │
                    └──────┬──────────┘
                           │
                    用戶聽到回覆
                    ┌──────▼──────────┐
                    │ GUI 更新狀態    │
                    │ └─ 廚房燈 ✅ ON  │
                    └─────────────────┘
```

**時間統計**：
- STT: 200-500ms (取決於語音長度)
- FastPath 匹配: 5-10ms ⚡
- GPIO 控制: <1ms
- TTS: 300-800ms
- **總耗時**: ~700ms-2秒 (通常 <1秒)

## 3. 複雜指令流向（FastPath → Gemini 降級）

### 場景：用戶說「晚上房間有點熱，可以調整一下嗎？」

```
用戶語音
    ↓ STT
「晚上房間有點熱，可以調整一下嗎？」
    ↓ 語言偵測
lang = "zh"
    ↓
┌─────────────────────────────────────┐
│ Agent 編排                          │
│                                     │
│ Step 1: FastPath 規則查詢           │
│ ├─ Pattern: "打開*燈", "關閉*", ... │
│ ├─ 「晚上房間有點熱」匹配不到      │
│ └─ ❌ FastPath 無法處理             │
│                                     │
│ Step 2: 記憶管理 (Memory Agent)    │
│ ├─ 檢查 user_rules                  │
│ ├─ 檢查 patterns                    │
│ └─ 仍無匹配                         │
│                                     │
│ Step 3: 決策 - 使用 Gemini API     │
│ └─ 因為本地無法解決                 │
└──────────────────┬──────────────────┘
                   │
        ┌──────────▼──────────┐
        │ Gemini Parser       │
        │ (GeminiParser)      │
        │                     │
        │ 發送 API 請求:      │
        │ {                   │
        │   "text": "晚上房間 │
        │   有點熱，可以調整  │
        │   一下嗎？",        │
        │   "lang": "zh",     │
        │   "context": {      │
        │     "devices": [...] │
        │     "state": {...}  │
        │   }                 │
        │ }                   │
        └──────────┬──────────┘
                   │ (HTTPS 呼叫)
        ┌──────────▼──────────┐
        │ [雲端] Gemini       │
        │                     │
        │ 理解: 用戶房間熱    │
        │ 建議: 風扇 + 開窗  │
        │ (或降溫)            │
        │                     │
        │ 回應:               │
        │ {                   │
        │   "actions": [      │
        │     {               │
        │       "type": "fan" │
        │       "action": "on"│
        │     }               │
        │   ],                │
        │   "explanation": "已│
        │   打開風扇"        │
        │ }                   │
        └──────────┬──────────┘
                   │ (回傳)
        ┌──────────▼──────────┐
        │ Agent 執行動作      │
        │ ├─ 風扇 ON          │
        │ ├─ 更新狀態         │
        │ └─ 儲存到記憶庫     │
        └──────────┬──────────┘
                   │
        ┌──────────▼──────────┐
        │ 學習模組            │
        │ (Memory Agent)      │
        │                     │
        │ 將此規則儲存:       │
        │ Pattern: "晚上房間  │
        │ 有點熱" → open_fan()│
        │                     │
        │ 下次直接 FastPath ⚡ │
        └──────────┬──────────┘
                   │
           TTS 回覆 + GUI 更新
```

**重點**：
- ✅ 第一次: Gemini API (~1-2秒)
- ✅ 第二次: FastPath (~0.1秒) 快 20 倍！
- 💡 系統持續學習，減少雲端依賴

## 4. 語言切換流程圖

```
使用者介面層
═══════════════════════════════════════════════════════

        [語言選擇器 OptionMenu]
        (初始化: self.lang = StringVar("zh"))
                │
                ├─ 選項 1: "中文" ────┐
                │                     │
                └─ 選項 2: "English"  │
                                      ▼
                    _on_language_change()
                    (事件處理函數)
                           │
         ┌─────────────────┼─────────────────┐
         │                 │                 │
         ▼                 ▼                 ▼
    更新字體        更新 UI 文字        通知排程系統
    ┌──────────┐   ┌──────────────┐  ┌──────────────┐
    │active_   │   │self.tr()查詢 │  │scheduler_    │
    │font_     │   │I18N 字典:    │  │runtime.      │
    │family    │   │             │  │on_language   │
    │          │   │"lang"→"語言" │  │_change()     │
    │zh_font   │   │"ok"→"確定"   │  │             │
    │or        │   │...          │  │ 後續輸出     │
    │en_font   │   └──────────────┘  │ 用新語言     │
    └─┬────────┘                     └──────────────┘
      │
      ▼
  [使用者看到 UI
   用新語言重新
   渲染]

核心系統層
═══════════════════════════════════════════════════════

當後續指令來時:

    用戶輸入
        ↓
    STT (自動偵測語言)
    例: 「Turn on fan」→ lang_input = "en"
        │
        ▼
    FastPath / Gemini
    (理解用戶意圖)
        │
        ▼
    format_reply_for_language(
        reply_text,
        gui_lang = self.lang.get()  ← 取 GUI 設定的語言
    )
        │
        ├─ 若 gui_lang == "zh": 翻譯回覆為中文
        │  「已打開風扇」
        │
        └─ 若 gui_lang == "en": 保持英文
           「Fan is now on」
        │
        ▼
    TTS (用 gui_lang 播出)
        │
        ▼
    用戶聽到相應語言的回覆
```

**關鍵設計**：
- 輸入語言由 STT 自動偵測（不受 GUI 語言影響）
- 輸出語言由 GUI 語言設定決定
- 完全解耦，無需重啟應用

```

├─ GPIO 輸出 (3.3V)
│  ├─ LED (直連 + 限流電阻)
│  └─ 繼電器 (光耦隔離)
│
音訊信號層
├─ 麥克風輸入 (USB → 數位)
└─ 喇叭輸出 (3.5mm 類比)

電源隔離
├─ GPIO 5V / 3.3V (邏輯電源)
├─ USB 5V (設備電源)
└─ 220V AC (繼電器通過光耦隔離)
```

## 7. 性能指標查看表（用於Q&A）

```
┌────────────────────────────────────────────────────┐
│         HomVoice 性能基準測試結果                  │
│              (Raspberry Pi 4)                      │
└────────────────────────────────────────────────────┘

指令類型              平均延遲        備註
─────────────────────────────────────────────────
FastPath (開燈/關門)   ~100ms ⚡     100% 本地
記憶規則查詢          ~50ms ⚡⚡     JSON 查詢
Gemini API 呼叫       1-2s           網路依賴
中文 TTS 生成         300-500ms      Piper 模型
英文 TTS 生成         200-400ms      Piper 模型
STT (中文語音辨識)    500-1000ms    取決於語音長度
GPIO LED 控制          <1ms          硬體層

總端對端延遲
─────────────────────────────────────────────────────
最佳情況 (FastPath): ~600ms
       = STT(500) + FastPath(50) + TTS(50)

平均情況 (一般指令): ~1.2s
       = STT(600) + 規則查詢(100) + TTS(300)

複雜指令 (Gemini): 2-3s
       = STT(600) + Gemini(1500) + TTS(400)

CPU 占用率 (空閒): 5-8%
CPU 占用率 (處理中): 25-35%
記憶體占用 (基礎): 150-200 MB
記憶體占用 (運行中): 300-500 MB
```

## 10. 圖表設計建議（投影用）

### 配色方案
```
🔵 主色 (邏輯層)     : RGB(0, 102, 204)    藍色
🟢 成功/本地        : RGB(76, 175, 80)     綠色
🟠 警告/雲端        : RGB(255, 152, 0)     橙色
🔴 錯誤            : RGB(244, 67, 54)      紅色
⚫ 背景            : RGB(240, 240, 240)    淺灰
```

### 字型建議
- 中文: 微軟正黑體 / 文泉驛正黑
- 英文: Source Code Pro (代碼)、Open Sans (文字)
- 標題: 20-24pt, 粗體
- 內容: 14-16pt, 正常

### 動畫呈現建議
1. **箭頭漸進動畫**：顯示數據流向
2. **顏色變化**：從灰色 → 對應顏色，表示激活
3. **數字動畫**：延遲時間從 0ms 漸進到最終值
